# АРМ оператора КП

Тестовое задание: веб-интерфейс рабочего места оператора. Получает по WebSocket список воздушных целей, показывает их в таблице и на схеме, отправляет команды обратно на сервер.

- `client/` — React 19, TypeScript, Zustand, Canvas, Vite
- `server/` — эмулятор бэкенда на FastAPI, `ws://localhost:8000/ws`

## Запуск

Нужны Node.js 22 и Python 3.10+.

Эмулятор:

```bash
cd server
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python simulator.py
```

По умолчанию шлёт 10 пакетов в секунду, `--hz 50` для нагрузки.

Интерфейс:

```bash
cd client
npm install
npm run dev
```

Открыть http://localhost:5173. Если сервер на другой машине:

```bash
VITE_WS_URL=ws://192.168.1.10:8000/ws npm run dev
```

`npm run build` собирает статику в `client/dist`. Внешних ресурсов нет (шрифт лежит в сборке, карта рисуется на Canvas), так что работает в сети без интернета.

## Что сделано

- Статус связи в шапке: ONLINE / RECONNECTING / OFFLINE, отсчёт до следующей попытки, кнопка «Переподключить». При потере связи поверх карты появляется предупреждение, а таблица и маркеры затемняются.
- Таблица целей: ID, тип, координаты, азимут, дальность, скорость, угроза. Высокая угроза подсвечена красным, средняя жёлтым. Фильтр по уровню угрозы, сортировка по клику на заголовок.
- Схема на Canvas: кольца дальности, охраняемая зона, следы и векторы движения. Форма маркера зависит от угрозы, так что её видно не только по цвету.
- Карточка цели открывается кликом в таблице или на карте. Кнопки «Передать в РЭБ», «Запросить видео», «Сбросить цель» отправляют JSON в сокет. РЭБ и сброс требуют подтверждения.
- Журнал событий, тревога при входе цели в охраняемую зону, стрелки ↑/↓ для переключения целей, Esc снимает выбор. Вёрстка работает и на узком экране.

## Решения

Пакеты идут двумя путями. Карта получает каждый пакет и рисует сама в `requestAnimationFrame`, без React. В стор Zustand раз в 250 мс уходит только последний пакет, поэтому таблица и карточка обновляются не чаще четырёх раз в секунду при любом потоке. Если цель не изменилась, в сторе остаётся тот же объект и строка таблицы не перерисовывается.

Между пакетами положение цели считается по скорости и курсу, а маркер плавно подтягивается к расчётной точке. Так нет рывков, когда приходят новые данные.

Выдернутый кабель браузер замечает не сразу: соединение может висеть минутами. Поэтому клиент сам следит за паузой между пакетами: после 1,5 с показывает предупреждение, после 4 с считает связь потерянной и переподключается. Пауза между попытками растёт от 0,5 до 10 с. ONLINE включается, только когда снова пошли данные, а не при открытии сокета.

Входящие пакеты проверяются: битый JSON и неправильные цели отбрасываются. Пакеты с меньшим `seq`, чем уже полученный, игнорируются. Команда без связи не отправляется. Если подтверждения нет 5 с, команда считается недоставленной.

Таймеры, слушатели и сокет закрываются при размонтировании. Журнал ограничен 200 записями, след цели 60 точками.

Под нагрузкой ~90 пакетов в секунду интерфейс держит 60 FPS, память не растёт.

## Проверка обрыва связи

Пока открыт интерфейс:

```bash
curl -X POST "localhost:8000/debug/stall?seconds=10"
curl -X POST localhost:8000/debug/drop
curl -X POST "localhost:8000/debug/rate?hz=100"
```

Первая команда останавливает данные без закрытия соединения (как выдернутый кабель), вторая разрывает соединение, третья увеличивает поток. Можно и просто остановить `simulator.py` и запустить снова.

## Тесты

```bash
cd client && npm test
cd server && pip install -r requirements-dev.txt && python -m pytest
```

На клиенте 29 тестов: переподключение и отслеживание тишины, очистка таймеров, ограничение частоты обновлений, сглаживание движения, команды, разбор сообщений. На сервере 5 тестов: обмен по WebSocket и логика симуляции.

## Протокол

Сервер шлёт `hello` при подключении, `telemetry` с полным списком целей и `ack` в ответ на команду:

```json
{ "type": "hello", "hz": 10, "rangeM": 10000, "zoneM": 2000, "base": { "lat": 51.1694, "lon": 71.4491 } }

{ "type": "telemetry", "seq": 812, "ts": 1794228810405, "targets": [
  { "id": "T-002", "type": "UAV", "x": 212.7, "y": 8786.3, "lat": 51.248329, "lon": 71.452148,
    "altitude": 409, "speed": 40.3, "azimuth": 1.4, "course": 199.3, "distance": 8789,
    "threat": "MEDIUM", "status": "TRACKING" } ] }

{ "type": "ack", "requestId": "m3k9x2-1", "action": "EW_HANDOFF", "targetId": "T-002", "ok": true, "message": "T-002 передана в модуль РЭБ" }
```

Клиент шлёт команду:

```json
{ "type": "command", "requestId": "m3k9x2-1", "action": "EW_HANDOFF", "targetId": "T-002", "ts": 1794228810500 }
```

`action`: `EW_HANDOFF`, `REQUEST_VIDEO` или `DROP_TARGET`.

## Структура клиента

```
src/
  types.ts            типы сообщений и цели
  config.ts           адрес сервера и тайминги
  net/
    TelemetrySocket.ts  сокет, переподключение, контроль тишины
    connection.ts       раздача пакетов карте и стору, команды
    protocol.ts         проверка входящих сообщений
  store/useArmStore.ts  состояние приложения
  map/trackBuffer.ts    треки и сглаживание для карты
  components/           шапка, таблица, карта, карточка, журнал
  hooks/                таймер, горячие клавиши
```
