# АРМ оператора локального КП

Это одностраничный интерфейс (SPA) рабочего места оператора. По WebSocket он получает в реальном времени телеметрию воздушных целей: показывает их в таблице и на 2D-схеме, а управляющие команды отправляет обратно на сервер.

В репозитории две части:

```
arm-operator/
├── client/   — интерфейс: React 19 + TypeScript + Zustand + Canvas (Vite)
└── server/   — эмулятор бэкенда: Python + FastAPI, ws://localhost:8000/ws
```

## Запуск

Нужны **Node.js 20+** и **Python 3.10+**.

### 1. Эмулятор бэкенда

```bash
cd server
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python simulator.py                # 10 пакетов/с
# python simulator.py --hz 50      # стресс-тест
```

### 2. Интерфейс

```bash
cd client
npm install
npm run dev                        # http://localhost:5173
```

Адрес сервера по умолчанию: `ws://localhost:8000/ws`. Для другой машины в локальной сети:

```bash
VITE_WS_URL=ws://192.168.1.10:8000/ws npm run dev
```

Production-сборка: `npm run build`, результат в `client/dist`. Это статические файлы, их можно раздавать любым веб-сервером в локальной сети.

**Работа без интернета.** Приложение не загружает ничего из сети: нет CDN, внешних шрифтов и тайлов карт. Схема рисуется на Canvas, используются системные шрифты.

## Что умеет

| Требование ТЗ | Реализация |
|---|---|
| Монитор соединения | В шапке статус `ONLINE` / `RECONNECTING` / `OFFLINE`, обратный отсчёт до следующей попытки, кнопка «Сейчас». Если данные задерживаются, статус становится жёлтым; при потере связи поверх карты появляется плашка «НЕТ СВЯЗИ», а таблица и маркеры затемняются. |
| Таблица целей | Поля ID, тип, координаты, дальность, азимут, скорость, угроза. Строки высокой угрозы красные, средней жёлтые. Фильтр по уровню угрозы, сортировка по клику на заголовок. |
| 2D-карта | Круговой обзор на Canvas: кольца дальности, азимуты, охраняемая зона, следы и векторы движения. Маркеры двигаются плавно (см. ниже). |
| Карточка и команды | Карточка открывается кликом по строке или маркеру. «Передать в РЭБ», «Запросить видео» и «Сбросить цель» отправляют JSON в WebSocket. Ответ сервера (`ack`) находится по `requestId`. Опасные команды требуют подтверждения оператора. |
| Дополнительно | Журнал событий, баннер «ВТОРЖЕНИЕ В ОХРАНЯЕМУЮ ЗОНУ», клавиши ↑/↓ (смена цели) и Esc, адаптивная вёрстка вплоть до 375 px. |

## Как это устроено

### Поток данных

```
WebSocket ──► TelemetrySocket ──► connection.ts ─┬─► trackBuffer (каждый пакет) ──► Canvas, каждый кадр (rAF)
 (сервер)     переподключение,                    │
              watchdog тишины                     └─► Zustand (последний пакет, раз в 250 мс) ──► таблица, карточка, шапка
```

### Производительность в real-time

- **React не перерисовывается на каждый пакет.** Сокет кладёт данные в буфер, а в стор раз в 250 мс уходит только последний срез. При 10 или при 100 пакетах в секунду интерфейс обновляется не чаще 4 раз в секунду.
- **Карта работает вне React.** Компонент рендерится один раз, рисование идёт в цикле `requestAnimationFrame`, данные читаются из буфера напрямую.
- **Плавное движение.** Между пакетами положение цели предсказывается по скорости и курсу. Рисуемая точка экспоненциально подтягивается к расчётной, поэтому новый пакет не даёт скачка. Без данных цель «додумывается» не дольше 2 с, после этого маркер затемняется.
- **Нормализация по id и стабильные ссылки.** Если данные цели не изменились, стор оставляет прежний объект, и `React.memo` пропускает перерисовку строки.
- Замер при ~90 пакетах/с: ровные 60 FPS, самый долгий кадр 17,7 мс, long tasks отсутствуют.

### Отказоустойчивость сети

- **Watchdog тишины.** При выдернутом Ethernet-кабеле TCP не закрывается сам, и браузер может минутами не получать `close`. Поэтому клиент сам следит за паузой: больше 1,5 с означает «данные задерживаются», больше 4 с означает, что связь потеряна, и клиент переподключается.
- **ONLINE только при реальном потоке данных**, а не в момент открытия сокета.
- **Экспоненциальная пауза между попытками** (0,5 → 1 → 2 → … → 10 с) со случайным разбросом, чтобы несколько АРМ не обращались к серверу одновременно.
- Тайм-аут на подключение. Реакция на события браузера `offline`/`online`.
- **Команды без связи не отправляются.** Оператор видит ошибку. Если подтверждение не пришло за 5 с, команда помечается как недоставленная.

### Утечки памяти

Всё, что создаётся, удаляется:
- `TelemetrySocket.dispose()` останавливает таймеры, отписывается от событий `window` и закрывает сокет; у старого сокета отвязываются обработчики;
- `useEffect` в компонентах возвращают очистку (rAF, `ResizeObserver`, слушатели);
- цели, пропавшие из потока, удаляются из буфера;
- журнал ограничен 200 записями, след цели 60 точками.

### Структура клиента

```
src/
├── types.ts              — протокол обмена (типы сообщений и цели)
├── config.ts             — адрес сервера и тайминги
├── net/
│   ├── TelemetrySocket.ts — WebSocket: переподключение, watchdog, очистка
│   └── connection.ts      — мост сокет → буфер карты / стор, отправка команд
├── store/useArmStore.ts  — Zustand: цели, связь, выбор, фильтры, команды, журнал
├── map/trackBuffer.ts    — треки для карты и сглаживание движения
├── components/           — Header, TargetTable, TacticalMap, TargetCard, EventLog
└── hooks/                — useNow (таймер), useKeyboard (горячие клавиши)
```

## Протокол

**Сервер → клиент**

```jsonc
// при подключении
{ "type": "hello", "hz": 10, "rangeM": 10000, "zoneM": 2000, "base": { "lat": 51.1694, "lon": 71.4491 } }

// 10 раз в секунду, полный список целей
{ "type": "telemetry", "seq": 812, "ts": 1794228810405, "targets": [
  { "id": "T-002", "type": "UAV", "x": 212.7, "y": 8786.3, "lat": 51.248329, "lon": 71.452148,
    "altitude": 409, "speed": 40.3, "azimuth": 1.4, "course": 199.3, "distance": 8789,
    "threat": "MEDIUM", "status": "TRACKING" } ] }

// ответ на команду
{ "type": "ack", "requestId": "m3k9x2-1", "action": "EW_HANDOFF", "targetId": "T-002", "ok": true, "message": "T-002 передана в модуль РЭБ" }
```

**Клиент → сервер**

```json
{ "type": "command", "requestId": "m3k9x2-1", "action": "EW_HANDOFF", "targetId": "T-002", "ts": 1794228810500 }
```

`action` принимает значения `EW_HANDOFF` (передать в РЭБ), `REQUEST_VIDEO` (запросить видео) и `DROP_TARGET` (сбросить цель).

## Как проверить отказоустойчивость

Пока открыт интерфейс, в отдельном терминале:

```bash
curl -X POST "localhost:8000/debug/stall?seconds=10"   # сервер молчит, TCP жив (как выдернутый кабель)
curl -X POST  localhost:8000/debug/drop                # сервер рвёт соединение
curl -X POST "localhost:8000/debug/rate?hz=100"        # поток 100 пакетов/с
```

Или просто остановите `simulator.py` (Ctrl+C) и запустите снова: интерфейс переподключится сам.
